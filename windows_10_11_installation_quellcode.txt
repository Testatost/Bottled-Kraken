Bottled Kraken v3.4 - Windows 10/11 Installation aus dem Quellcode
=======================================================================

Diese Anleitung ist fuer Windows 10 und Windows 11 gedacht.
Die Befehle werden Schritt fuer Schritt in PowerShell im Projektordner ausgefuehrt.

Voraussetzungen
---------------
- Windows 10 oder Windows 11, 64 Bit
- Python 3.13.x, 64 Bit, mit aktivierter Option "Add python.exe to PATH"
  Alternativ wird vom Buildskript auch Python 3.12 x64 akzeptiert.
- PowerShell 5.1 oder PowerShell 7
- Der Bottled-Kraken-Quellcode liegt entpackt in einem kurzen Projektpfad, zum Beispiel C:\bk
- Internetzugang fuer pip, PyTorch-CPU-Wheels, Kraken, Whisper und eScriptorium/WSL-Downloads
- Fuer Pakete ohne passende Wheels: Visual C++ Build Tools

Wichtig zum Windows-Build
-------------------------
Der Windows-Release-Build sollte nicht mehr manuell mit einer normalen .venv gebaut werden.
Verwende fuer den Release-Build bevorzugt das mitgelieferte Skript:

    Set-ExecutionPolicy -Scope Process Bypass
    .\build_windows_10_11.ps1

Das Skript erstellt eine eigene Build-Umgebung:

    .venv-win

und installiert die gesperrten Windows-Abhaengigkeiten aus:

    requirements-lock-windows.txt

Dadurch bleiben Kraken, PyTorch, PyInstaller, Whisper/faster-whisper und die Windows-Laufzeitpakete reproduzierbar.

Vorpruefung der Build-Umgebung
------------------------------
Optional vor dem Build ausfuehren:

    .\check_windows_10_11_build_environment.ps1

Das prueft unter anderem:
- 64-Bit-Python 3.13 oder 3.12
- Projektpfadlaenge
- Windows-Langpfade
- icon.ico
- Visual C++ Build Tools
- WSL2-Status fuer eScriptorium

1. PowerShell oeffnen und in den Projektordner wechseln
-------------------------------------------------------
Beispiel:

    cd "C:\bk"

Oder, falls der Ordner im Benutzerprofil liegt:

    cd "$env:USERPROFILE\PycharmProjects\Bottled Kraken"

2. Release-Build erstellen
--------------------------

    Set-ExecutionPolicy -Scope Process Bypass
    .\build_windows_10_11.ps1

Die fertige Windows-EXE liegt danach unter:

    dist\Bottled Kraken.exe

3. Sauberen Neubuild erzwingen
------------------------------
Falls noch eine alte oder fehlerhafte Build-Umgebung vorhanden ist, zuerst loeschen:

    Remove-Item -Recurse -Force .venv-win, build, dist -ErrorAction SilentlyContinue

Danach erneut bauen:

    .\build_windows_10_11.ps1

4. Tests ueberspringen, falls nur schnell gebaut werden soll
-----------------------------------------------------------

    .\build_windows_10_11.ps1 -SkipTests

Fuer Release-Builds sollten die Tests normalerweise nicht uebersprungen werden.

5. Lockfile neu erzeugen, falls Abhaengigkeiten bewusst aktualisiert werden
--------------------------------------------------------------------------

    .\build_windows_10_11.ps1 -RegenerateLock

Das erzeugt:

    requirements-lock-windows.generated.txt

Diese Datei danach manuell pruefen und nur bei Bedarf nach:

    requirements-lock-windows.txt

uebernehmen.

Hinweis zu Kraken und .mlmodel unter Windows
--------------------------------------------
Bottled Kraken v3.4 muss klassische Kraken-.mlmodel-Dateien auch unter Windows laden koennen.
Dafuer muss coremltools in der Windows-Buildumgebung vorhanden sein.

Kraken wird zwar weiterhin mit:

    python -m pip install --no-deps kraken==7.0.3

installiert, damit die Windows-Abhaengigkeiten kontrolliert bleiben.
coremltools darf aber nicht fehlen, weil Kraken klassische .mlmodel-Dateien darueber einliest.

Der automatische Build prueft deshalb:

    python -m pip check
    python -c "import kraken; print('kraken OK')"
    python -c "import coremltools; from coremltools.models import MLModel; from coremltools.proto import NeuralNetwork_pb2; print('coremltools OK')"
    python -c "import pkg_resources, backports.tarfile, faster_whisper; print('runtime OK')"

Wenn coremltools fehlt, kann es beim OCR-Start zu Fehlern wie diesem kommen:

    TypeError: the JSON object must be str, bytes or bytearray, not _CoreMLStubMessage
    KrakenInvalidModelException: File ... not loadable by any parser.

In diesem Fall die alte .venv-win loeschen und mit dem korrigierten Buildskript neu bauen.

6. Programm aus dem Quellcode starten, ohne Release-Build
--------------------------------------------------------
Fuer Entwicklung/PyCharm kann weiterhin eine normale virtuelle Umgebung verwendet werden.
Empfohlen fuer Windows v3.4:

    py -3.13 -m venv .venv
    Set-ExecutionPolicy -Scope Process Bypass
    .\.venv\Scripts\Activate.ps1
    python -m pip install --upgrade pip wheel
    python -m pip install "setuptools==80.10.2" "backports.tarfile==1.2.0"
    python -m pip install -r requirements-lock-windows.txt
    python -m pip install --no-deps kraken==7.0.3
    python -m pip check
    python main.py

7. Fertige EXE starten
----------------------

    & ".\dist\Bottled Kraken.exe"

8. Installierte Versionen pruefen
---------------------------------

    python - <<'PY'
    import sys
    import torch
    import torchvision
    import kraken
    import coremltools
    from coremltools.models import MLModel
    from coremltools.proto import NeuralNetwork_pb2

    print("python:", sys.version)
    print("torch:", torch.__version__)
    print("torchvision:", torchvision.__version__)
    print("kraken:", getattr(kraken, "__version__", "unknown"))
    print("coremltools:", getattr(coremltools, "__version__", "unknown"))
    print("torch CUDA:", torch.version.cuda)
    print("CUDA available:", torch.cuda.is_available())
    PY

Fuer die normale CPU-Version ist es in Ordnung, wenn dort steht:

    torch CUDA: None
    CUDA available: False

Hinweis zur CPU-Version
-----------------------
Die Standard-App ist als CPU-Onefile-Version gedacht.
Kraken OCR ist trotzdem direkt enthalten, weil Kraken das Kernfeature von Bottled Kraken ist.

CUDA wird nicht direkt in die Haupt-App eingebettet.
Das haelt die EXE kleiner und vermeidet viele Installationsprobleme.

Hinweis zu NVIDIA CUDA
----------------------
NVIDIA CUDA kann direkt aus Bottled Kraken heraus als externes Backend installiert werden:

    Optionen -> CPU/GPU -> GPU - CUDA (NVIDIA) -> CUDA (NVIDIA) installieren

Das CUDA-Backend wird separat im Benutzerprofil installiert:

    %LOCALAPPDATA%\BottledKraken\backends\nvidia-cuda

Die CPU-Onefile-App wird dadurch nicht veraendert.

Wichtig:
- Ein funktionierender NVIDIA-Treiber muss installiert sein.
- Die Backend-Installation veraendert keine systemweiten CUDA-Installationen.
- Die Backend-Installation deinstalliert keine systemweiten NVIDIA-Treiber.
- Wenn kein CUDA-Backend vorhanden ist, verwendet Bottled Kraken automatisch CPU-OCR.

Optionaler CUDA-Backend-Selbsttest
----------------------------------
Nach der CUDA-Backend-Installation kann der Selbsttest so ausgefuehrt werden:

    & "$env:LOCALAPPDATA\BottledKraken\backends\nvidia-cuda\.venv\Scripts\python.exe" "$env:LOCALAPPDATA\BottledKraken\backends\nvidia-cuda\worker_kraken_backend.py" --self-test --backend-kind nvidia-cuda

Wenn alles funktioniert, sollte dort unter anderem stehen:

    "ok": true
    "cuda_available": true
    "device_name": "..."

Typische Problembehebung
------------------------
1. PowerShell blockiert die Aktivierung der venv:

    Set-ExecutionPolicy -Scope Process Bypass
    .\.venv\Scripts\Activate.ps1

2. Alte Windows-Buildumgebung enthaelt noch den fehlerhaften CoreML-Stub-Build:

    Remove-Item -Recurse -Force .venv-win, build, dist -ErrorAction SilentlyContinue
    .\build_windows_10_11.ps1

3. requirements-lock-windows.txt wurde nicht gefunden:

    Pruefen, ob die Datei im Projektwurzelverzeichnis liegt.
    Fuer Release-Builds nicht einfach requirements.txt verwenden.

4. PyInstaller-Build soll sauber neu gestartet werden:

    Remove-Item -Recurse -Force build, dist -ErrorAction SilentlyContinue
    python -m PyInstaller --clean --noconfirm main.spec

5. CUDA-Backend soll komplett neu installiert werden:

    Remove-Item -Recurse -Force "$env:LOCALAPPDATA\BottledKraken\backends\nvidia-cuda"

Danach Bottled Kraken neu starten und CUDA erneut ueber das Menue installieren.

Kurzfassung
-----------
Fuer den normalen Windows-Release-Build:

    cd "C:\bk"
    Set-ExecutionPolicy -Scope Process Bypass
    Remove-Item -Recurse -Force .venv-win, build, dist -ErrorAction SilentlyContinue
    .\build_windows_10_11.ps1

Die fertige EXE liegt danach hier:

    dist\Bottled Kraken.exe
